# Screen — Product form

- **Routes:** `/productos/nuevo` and `/productos/:id/editar`
- **Feature:** [Product catalog](../features/productos.md)
- **Design reference:** Layout specification in the UI regions table below. No external mockup is provided.

---

## Purpose

Allow users to create or edit a product through one reusable form. Validate input before submission and display any validation messages returned by the API.

---

## UI regions

| Region | Component | Notes |
|--------|-----------|-------|
| Header | IonHeader, IonToolbar, IonTitle, IonBackButton | Display "New product" or "Edit product" according to the route. |
| Name field | IonInput | Required text with a maximum of 60 characters. |
| Price field | IonInput | Numeric input greater than zero, expressed in COP. |
| Category field | IonSelect, IonSelectOption | Offer Bebidas, Snacks, Aseo and Hogar. |
| Stock field | IonInput | Integer input greater than or equal to zero. |
| Field feedback | IonText | Display validation messages beside the corresponding fields. |
| Request feedback | IonSpinner, IonText | Display loading, saving and server error messages. |
| Primary action | IonButton | "Create product" or "Save changes", according to the mode. |
| Secondary action | IonButton | Cancel and return to the list or product detail. |

The ID is generated by the API and cannot be edited.

---

## States

| State | Trigger | UI |
|-------|---------|-----|
| Empty / create | The creation route opens | Show an empty form with no validation errors until interaction or submission. |
| Loading | Edit mode requests the existing product | Show a spinner before enabling the form. |
| Loaded / editing | Product data is ready or the user enters values | Show editable fields. |
| Invalid input | validateProduct detects problems | Show inline messages and prevent the API request. |
| Saving | A valid POST or PUT request is pending | Show progress and disable repeated submission. |
| Server rejection | The API rejects the submitted values | Preserve form values and display the error and its details messages. |
| Not found | The edit request returns 404 | Show "Product not found" and a back-to-list action. |
| Invalid ID | The edit route contains an invalid identifier | Show an invalid-identifier message and a back-to-list action. |
| Error | Loading or saving fails for another reason | Show the error; allow retry when loading and resubmission when saving. |
| Offline | A network request fails because connectivity is unavailable | Show a connection message. Preserve entered values when saving fails. |
| Success | The API creates or updates the product | Navigate to `/productos/:id` using the returned product ID. |

---

## Actions

| User action | Result | Use case / event |
|-------------|--------|------------------|
| Open the creation route | Initialize a new form | Initialize create mode |
| Open the edit route | Load the product and populate the form | getProduct |
| Change a field | Update local form state and validation feedback after interaction | validateProduct |
| Submit invalid values | Display inline errors without sending a request | validateProduct |
| Submit valid values in create mode | Send POST /api/products | createProduct |
| Submit valid values in edit mode | Send PUT /api/products/:id | updateProduct |
| Receive a server rejection | Display ApiError.details and preserve input | Handle API error |
| Select Retry after a loading failure | Request the product again | getProduct |
| Select Cancel in create mode | Return to `/productos` | Cancel creation |
| Select Cancel in edit mode | Return to `/productos/:id` | Cancel editing |

---

## Validation

The form uses the domain function `validateProduct` with the same rules as the API:

- Name must be a nonblank string with a maximum of 60 characters.
- Price must be a number greater than zero.
- Category must be Bebidas, Snacks, Aseo or Hogar.
- Stock must be an integer greater than or equal to zero.

Blank numeric fields must not silently become zero. Convert nonblank numeric
values before validation and submission.

## Accessibility

The following requirements will be checked during UI verification.

- [ ] All fields and buttons have accessible labels.
- [ ] Validation messages are associated with their fields.
- [ ] Touch targets are at least 48 × 48 CSS pixels.
- [ ] Text remains readable when the browser font size or zoom increases.
- [ ] Text and controls meet WCAG AA contrast requirements.
- [ ] Required fields and errors are indicated by more than color alone.
- [ ] Loading, saving and error feedback is available to assistive technologies.
- [ ] The form works with a keyboard.
