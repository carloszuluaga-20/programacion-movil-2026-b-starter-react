# Product Entity — Product

- **Store:** N/A for persistent storage. Products are stored in Express server memory.
- **Table/collection:** In-memory products array.
- **Initial data source:** `server/data/products.json`
- **Schema version introduced:** N/A. No database schema or migrations are used.
- **Feature:** [Product catalog](../features/productos.md)

---

## Fields

| Field | Type | Null | Notes |
|---|---|---|---|
| id | number | No | Unique identifier generated by the API. New IDs are incremental. |
| name | string | No | Required, nonblank text with a maximum of 60 characters. Trimmed before storage. |
| price | number | No | Finite price in Colombian pesos, greater than zero. |
| category | string | No | One of Bebidas, Snacks, Aseo or Hogar. |
| stock | number | No | Integer quantity greater than or equal to zero. |

POST and PUT receive `name`, `price`, `category` and `stock`.
The API generates the ID on creation and preserves it during updates.
Deleted IDs are not reused within the same server session.

No `created_at` or `updated_at` fields are required by the API contract.

### Example

```json
{
  "id": 1,
  "name": "Agua mineral 600 ml",
  "price": 1800,
  "category": "Bebidas",
  "stock": 120
}
```

### Kotlin representation

The separate Kotlin exercise uses the same field names:

| Field | Kotlin type | Mutability |
|---|---|---|
| id | Int | val |
| name | String | var |
| price | Double | var |
| category | String | var |
| stock | Int? | var |

The stock field defaults to null when omitted.

Nullable stock belongs only to the Kotlin exercise.
The API and Ionic form require a nonnegative integer stock value.

## Sync

- **Synced?** No persistent synchronization or offline queue.
- **Conflict policy:** Each successful PUT replaces the editable fields of the current in-memory product. No version-based conflict detection is implemented.
- **Client refresh:** Pages request current API data when becoming active again.
- **Offline behavior:** Connection failures show an error message. Form values are preserved when saving fails.
- **Successful mutations:** Creation, editing and deletion return to `/productos`, where the catalog refreshes.
- **Server restart:** The initial eight products are loaded again; runtime changes are lost.

## Migration notes

N/A, in-memory storage. No database migration is required.

The JSON file supplies the initial catalog and is not rewritten by CRUD
operations. Any future persistent-storage implementation would require
a separate architecture decision and an update to this document.

## Presentation mapping

The domain `Product` preserves the API field values.

`toProductView` trims the name, uses `formatCOP` for the display price,
and derives stock labels and flags:

| Stock quantity | Label | isOutOfStock | isLowStock |
|---|---|---|---|
| 0 | Agotado | true | false |
| 1 to 4 | Pocas unidades | false | true |
| 5 or more | Disponible | false | false |

Prices use Colombian peso formatting, for example `$ 1.250.000`.

The Kotlin `stockLabel` function additionally returns `Sin dato` for null.
