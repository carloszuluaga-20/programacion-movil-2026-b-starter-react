# Feature — Product catalog

- **Owner:** carloszuluaga-20
- **Status:** In progress
- **Related stories:** CAT-001 List and filter products; CAT-002 View details; CAT-003 Create products; CAT-004 Edit products; CAT-005 Delete products.

## Purpose

Allow users to consult and manage a product catalog through an Ionic React application connected to an Express API. Users can search, filter, view, create, edit and delete products.

## State

- **Pattern:** Local page state with React `useState` and `useEffect`, organized into data, domain and presentation layers.
- **Page refresh:** `useIonViewWillEnter` reloads data when users return to pages retained in memory by Ionic.
- **State values:** Products, selected product, search text, category filter, form values, validation errors, loading status, request errors, saving, deleting and delete confirmation.

Key transitions:

| Flow | Transitions |
|---|---|
| List loading | Loading → loaded, empty or error |
| Retry | Error → loading → loaded or error |
| Filtering | Loaded → matching products or no results |
| Detail loading | Loading → loaded, not found or error |
| Form submission | Ready → validation errors or saving → list or API error |
| Deletion | Viewing → confirmation → deleting → list or error |

State updates use React setters without mutating existing arrays or objects.

Successful creation, editing and deletion return users to `/productos`.

## Data

- **Use cases:** Load products, filter products, load one product, validate input, create, update and delete products.
- **Repositories:** No separate repository class is used. The data-layer HTTP client centralizes API access.
- **Remote endpoints:** See [Product endpoints](../api/products-endpoints.md).

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/products` | Load products with optional search and category filters |
| GET | `/api/products/:id` | Load one product |
| POST | `/api/products` | Create a product |
| PUT | `/api/products/:id` | Update a product |
| DELETE | `/api/products/:id` | Delete a product |

- **API filters:** `search` matches part of the name without case sensitivity; `category` uses an exact match. Both filters can be combined.
- **App filters:** `filterProducts` applies search and category filters to the loaded list.
- **Local persistence:** None. The API loads eight initial products from `server/data/products.json` and stores changes in memory. Restarting the server restores the initial data.
- **Identifiers:** New product IDs are incremental and generated by the API. Editing preserves the ID, and deleted IDs are not reused within the same server session.
- **Offline behavior:** There is no persistent cache or offline write queue. Failed saves preserve the current form values for resubmission.

### Validation rules

The API and the app enforce the same rules:

- `name`: Required string, not blank, maximum 60 characters.
- `price`: Required finite number greater than zero.
- `category`: One of `Bebidas`, `Snacks`, `Aseo` or `Hogar`.
- `stock`: Required integer greater than or equal to zero.

The form validates on submission and displays errors beside the corresponding fields. Invalid input prevents the API request.

API errors follow `{ "error": "message", "details": ["..."] }`.
Validation responses include one entry in `details` for each detected problem.

The HTTP client represents connection failures and unsuccessful API responses with `ApiError`.

### Product presentation

`toProductView` trims the product name, formats the price using `formatCOP`, and provides a stock label:

- `0`: `Agotado`
- `1` to `4`: `Pocas unidades`
- `5` or more: `Disponible`

The `isOutOfStock` and `isLowStock` flags match these stock labels.

Category buttons use the exact API category values.

## Edge cases & states

These requirements are implemented. Check each item after completing its verification.

- [ ] Loading indicators while requesting data.
- [ ] Empty catalog message when the API returns no products.
- [ ] Separate no-results message when filters match no products.
- [ ] List error message with a retry button.
- [ ] Clear message for network or offline failures.
- [ ] Clear handling of invalid or nonexistent product IDs.
- [ ] Inline validation and server `details` messages in the form.
- [ ] Confirmation before deleting a product.
- [ ] Return to the list after successful creation, editing and deletion.
- [ ] Prevent repeated submissions while saving or deleting.
- [ ] Preserve entered form values when saving fails.

Permission handling is not applicable because this feature does not require authentication or device permissions.

## Tests

- **Unit:** Automated tests cover `validateProduct`, `toProductView` and `filterProducts`, including invalid inputs, stock boundaries and combined filters.
- **UI verification:** Manually check list states, navigation, form validation, retry and deletion confirmation.
- **Integration:** Automated API tests cover CRUD operations, filters, validation, status codes and error structure using `startTestServer()`.
- **Error handler:** An automated test requests an unknown route to verify the supplied 404 handler. Its behavior is explained in the README.
- **End-to-end verification:** Manually create a product, view its detail, edit it, delete it and verify the updated list.
