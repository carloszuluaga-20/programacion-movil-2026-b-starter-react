# Feature — Product catalog

- **Owner:** carloszuluaga-20
- **Status:** Planned
- **Related stories:** CAT-001 List and filter products; CAT-002 View details; CAT-003 Create products; CAT-004 Edit products; CAT-005 Delete products.

## Purpose

Allow users to consult and manage a product catalog through an Ionic React application connected to an Express API. Users can search, filter, view, create, edit and delete products.

---

## Screens

| Screen | Route | Purpose |
|--------|-------|---------|
| Product list | `/productos` | List products, search by name and filter by category. |
| Product detail | `/productos/:id` | Show all fields and provide edit and delete actions. |
| Create product | `/productos/nuevo` | Create a product using the shared form. |
| Edit product | `/productos/:id/editar` | Load and update a product using the shared form. |

## State

- **Pattern:** Local page state with React `useState` and `useEffect`, organized into data, domain and presentation layers.
- **State objects:** Products, selected product, search text, category filter, form values, validation errors, loading, request error, saving, deleting and delete confirmation.
- **Key transitions:**
  - List: loading → loaded, empty or error.
  - Retry: error → loading → loaded or error.
  - Filters: loaded → matching products or no results.
  - Detail: loading → loaded, not found or error.
  - Form: editing → validation errors or saving → success or API error.
  - Delete: viewing → confirmation → deleting → list or error.

State updates use React setters without mutating existing arrays or objects.

## Data

- **Use cases:** Load products, filter products, load one product, validate input, create, update and delete products.
- **Repositories:** No separate repository class is required. The data-layer HTTP client centralizes API access.
- **Remote sources / endpoints:**
  - `GET /api/products`
  - `GET /api/products/:id`
  - `POST /api/products`
  - `PUT /api/products/:id`
  - `DELETE /api/products/:id`
- **API filters:** `search` matches part of the name without case sensitivity; `category` uses an exact match. Both filters can be combined.
- **App filters:** `filterProducts` applies search and category filters to the loaded list.
- **Local persistence:** None. The API loads eight initial products from `server/data/products.json` and stores changes in memory. Restarting the server restores the initial data.
- **Identifiers:** New product IDs are incremental and generated by the API.

### Validation rules

The API and the app enforce the same rules:

- `name`: Required string, not blank, maximum 60 characters.
- `price`: Required number greater than zero.
- `category`: One of `Bebidas`, `Snacks`, `Aseo` or `Hogar`.
- `stock`: Required integer greater than or equal to zero.

API errors follow `{ "error": "message", "details": ["..."] }`.
Validation responses include one entry in `details` for each detected problem.

### Product presentation

`toProductView` formats the price using `formatCOP` and provides a stock label:

- `0`: `Agotado`
- Less than `5`: `Pocas unidades`
- `5` or more: `Disponible`

## Edge cases & states

These are planned requirements. Check them after verification.

- [ ] Loading indicators while requesting data.
- [ ] Empty catalog message when the API returns no products.
- [ ] Separate no-results message when filters match no products.
- [ ] List error message with a retry button.
- [ ] Clear message for network or offline failures.
- [ ] Clear handling of invalid or nonexistent product IDs.
- [ ] Inline validation and server `details` messages in the form.
- [ ] Confirmation before deleting a product.
- [ ] Return to the list after successful deletion.
- [ ] Prevent repeated submissions while saving or deleting.

Permission handling is not applicable because this feature does not require authentication or device permissions.

## Tests

- **Unit:** Test `validateProduct`, `toProductView` and `filterProducts`, including invalid inputs, stock boundaries and combined filters.
- **Widget/UI:** Manually verify list states, navigation, validation, retry and delete confirmation.
- **Integration:** Test API CRUD, filters, validation, status codes and error structure using `startTestServer()`.
- **Error handler:** Request an unknown route to verify the provided 404 handler and explain its behavior in English.
- **End-to-end:** Manually create a product, view its detail, edit it, delete it and verify the updated list.
